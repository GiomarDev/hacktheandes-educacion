# ms-escale (F4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Servicio de indicadores: importa los CSV oficiales de `docs/`, calcula agregados diarios por IE e indicadores mensuales por UGEL, y los expone filtrados por alcance.

**Architecture:** `apps/ms-escale` (puerto 3004, schema `escale`) con el mismo patrón que ms-simon: Prisma 7 con adapter-pg, JWT vía JWKS, rutas internas con `x-internal-key`. Los parsers de CSV son funciones puras con pruebas unitarias. Los agregados diarios se piden por API a ms-siagie y ms-alerta; ms-escale nunca lee tablas ajenas.

**Tech Stack:** NestJS 12 ESM, TypeScript 6, Prisma 7.10.1, PostgreSQL 17, Vitest + Supertest.

**Spec:** `docs/superpowers/specs/2026-10-17-backend-microservicios-design.md` (secciones 4.4, 5 y fase F4).

## Global Constraints

- Schema `escale`; pruebas solo en `escale_test` (protegido por `test/test-databases.ts`).
- Verificación de F4: los totales importados cuadran con `desercion_por_region_siagie_2023_2024.csv` (secundaria 72 282 / 2 842 831, primaria 64 463 / 3 721 852).
- `dataset_imports.checksum` sha256: el mismo archivo no se importa dos veces (409).
- Unique de `indicator_values` (indicator_id, geo_level, geo_code, period_label, dimension, dimension_value) con `NULLS NOT DISTINCT`.
- Sin seeds en schemas reales. El catálogo de indicadores se inserta en la migración (son datos de referencia, no datos personales).
- `BACKGROUND_JOBS_ENABLED=false` desactiva el job diario.
- No imprimir URLs de conexión ni datos personales en logs.

## Review Focus

1. Nombres de región con tildes perdidas por la codificación (`Apurmac`, `Hunuco`, `Junn`, `San Martn`, `Pblica`) y BOM al inicio: deben reconocerse, no descartarse.
2. Celdas vacías o filas con porcentaje que no cuadra con desertores/estudiantes: la importación completa se rechaza con 400 y no deja nada a medias.
3. Un especialista de UGEL no ve indicadores calculados de otra UGEL; los oficiales (datos abiertos) los ve cualquier usuario autenticado.
4. Días sin clases (sábado y domingo) no generan "aulas en silencio".
5. Una fuente caída durante el job no borra agregados existentes y el resto de IEs se procesa.

### Task 3: Importaciones e indicadores (API)

**Interfaces:**

### Task 4: Agregados diarios e indicadores por UGEL

**Files:**
- Create: `apps/ms-siagie/src/internal/escale-context.controller.ts`; `apps/ms-escale/src/{clients.ts,stats.service.ts,jobs.service.ts}`; `apps/ms-escale/test/stats.e2e-spec.ts`
- Modify: `libs/common/src/reporting/contracts.ts` (`currentlyContactedOpenCases`), `apps/ms-alerta/src/reporting.controller.ts`, módulo de siagie.

**Interfaces:**
- siagie `GET /internal/escale/schools` → `[{ id, modularCode, name, ugel: { id, code, name }, dre: { id, code, name } }]`.
- `StatsService.compute(date: string): Promise<{ date, schools, computed, failed, skipped }>`; sábados y domingos → `skipped: true` sin escribir.
- `POST /stats/compute { date }` (MINEDU_ADMIN). Job: cada hora comprueba; corre una vez por día para el día anterior en Lima.
- Mapeo: `present = PRESENT + LEFT_EARLY`, `late = LATE`, `absent = ABSENT + JUSTIFIED` (así la tasa coincide con la de SIAGIE).
- Indicadores mensuales por UGEL (`period 'YYYY-MM'`): `ATTENDANCE_RATE = (present+late)/(present+late+absent)`, `SILENT_SECTIONS_RATE = (Σtotal − Σreported)/Σtotal`, `CASES_CONTACTED_RATE = contacted/open` del último día calculado. Denominador 0 → no se escribe.

- [ ] Tests e2e con auth, siagie, alerta y escale reales: dos IEs de la misma UGEL, una sección sin pase de lista → `sectionsReported` y `SILENT_SECTIONS_RATE` correctos; asistencia coincide con la tasa de SIAGIE; repetir el cálculo no duplica filas; sábado → skipped; alerta caída → `failed` y sin borrar filas previas.
